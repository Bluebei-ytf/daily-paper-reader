## 摘要
化学问题往往需要精确的计算和数据库查询，而这些是语言模型无法仅凭其参数提供的，因此它必须借助外部工具。这里的工具使用包含三个部分的问题：从大量工具中选择正确的工具，为它填入类型正确的参数，并链式调用以便每个调用都消费上一个调用的输出。CheMatAgent 是一个先前发表的系统，通过分层进化 MCTS 解决这个问题：分离的策略和执行模型在两个学习到的评论家指导下搜索工具调用树，其中一个是部分回归到 GPT 分配的分数上。我们证明一个单一策略就足够了。我们的模型在一次从左到右的生成中交织推理、工具调用和返回，通过监督预热训练，然后针对程序化奖励进行结果级强化学习，该奖励直接从金标准调用链中读取，这避免了训练循环中的学习评论家和评判者。在 ChemToolBench 多工具综合化学基准上，在 CheMatAgent 使用的两个骨干网络上，与它们最强的搜索配置相比，我们在 Qwen-2.5-7B 上将 Tool F1 提高了 5.5%，Return F1 提高了 9.6%，在 Llama-3.1-8B 上分别提高了 3.7% 和 3.9%，而每个问题只进行一次模型调用，而搜索的成本随树增长；我们还在 Qwen-2.5-7B 上领先了答案通过率。

## Abstract
Chemistry questions often demand exact computation and database lookups that a language model cannot supply from its parameters, so it must reach for external tools. Tool use here is a three-part problem: select the right tool from a large pool, fill it with correctly typed arguments, and chain calls so that each consumes the outputs of the last. CheMatAgent, a previously published system, addresses this with hierarchical evolutionary MCTS: separate policy and execution models searching tool-call trees under two learned critics, one regressed partly onto GPT-assigned scores. We show that a single policy suffices. Our model interleaves reasoning, tool calls, and returns in one left-to-right generation, trained by a supervised warm-up and then outcome-level reinforcement learning against a programmatic reward read directly off the gold call chain, which leaves no learned critic and no judge in the training loop. On ChemToolBench multiple-tool comprehensive chemistry, on both backbones CheMatAgent use, we improve Tool F1 by 5.5% and Return F1 by 9.6% on Qwen-2.5-7B, and by 3.7% and 3.9% on Llama-3.1-8B, compared with their strongest search configuration, at one model invocation per question, against a search whose cost grows with the tree; we also lead answer Pass Rate on Qwen-2.5-7B.

## 1. 论文的核心问题与整体含义（研究动机与背景）

化学领域的问答任务常常要求**精确计算**和**数据库查询**，这是语言模型（LLM）无法仅凭其参数完成的，因此模型必须借助外部工具。化学工具学习存在三大挑战：

- **工具选择难**：化学工具高度专业化，规模可达上百种，且许多工具接口相似但科学假设和输入要求微妙不同，准确选择工具是一项推理任务而非简单检索。
- **参数生成难**：工具参数多为 SMILES 字符串、分子标识符、化学式等结构化学表示，要求严格的结构有效性和计算精度，任何语法或语义错误都可能导致执行失败或科学错误。
- **长链条依赖**：化学问题往往涉及多个有依赖关系的工具调用——后续工具的参数来自前面调用的返回值，早期错误会在执行轨迹中传播放大。

此前该方向的最强系统是 **CheMatAgent**，它的解决方式是**分层进化蒙特卡洛树搜索（HE-MCTS）**：分别用一个策略模型选择工具、另一个执行模型填充参数，在训练过程中训练两个学习的 critic（过程奖励模型 PRM + 结果奖励模型 ORM，后者部分回归到 GPT 分配分数），再用搜索结果微调策略。该方法效果好但管线非常庞大、推理成本高——涉及四个模型，每问一次请求的模型调用次数随搜索树规模增长。

论文提出的核心问题是：这套复杂的搜索机器是否必要？作者沿着 **可验证奖励强化学习（RLVR）** 的思路，证明答案是**否定的**——一个单一的、端到端训练的、交替推理并调用真实工具的 LLM 策略，就能在多个指标上超越 CheMatAgent 的 HE-MCTS，而每次提问仅需一次模型调用。

## 2. 论文提出的方法论

### 2.1 核心思想

用**一个策略模型 πθ** 在单次自回归生成中完成全部工作：让模型依次输出 `<think>` 推理块 → `<tool_call>` 工具调用 → 等待真实工具返回 `<tool_result>` → 再推理、再调用……直到输出 `Answer:`。将这一过程称为 **rollout protocol（回滚协议）**。训练分为两阶段：监督微调（SFT）预热 + 基于可验证奖励的强化学习。**全过程不训练任何 critic 模型，不使用 LLM 裁判。**

### 2.2 关键技术细节

**（1）单代理工具使用 rollout 协议（§4.1）**
- 模型最多与环境交互 16 轮。
- 每轮输出一句 `<think>` 推理 + 一个 JSON 格式的 `<tool_call>`（如 `{"name": "<lib>/<func>", "arguments": {...}}`）。
- 工具服务器执行调用，将真实返回追加为 `<tool_result>` 跨度；该跨度由服务器生成，**在训练损失中被 mask 掉**，模型只在自己的 tokens 上学习。
- 当模型输出单行 `Answer:` 或预算耗尽时，一个 episode 结束。
- 值得注意的是，训练过程也执行**真实的工具调用**（而非模拟的返回结果），使模型能真正学会读取并利用先前输出值。

**（2）监督微调 warm-up（§4.2）**
- 将每条金标准调用链线性化为 rollout 轨迹格式（推理块→调用→返回交替），并以完整自然语言句子作为最终答案。
- 可以只从基础模型出发做 RL（RL-only），也可以先 SFT 再 RL（SFT→RL）。发现 SFT 效果不亚于单独做 RL。

**（3）程序化奖励设计（§4.3）**
所有奖励完全由程序从金标准调用链 C 计算得出，映射到 [−1, 1]，不需要学习或 LLM 裁判。给出五种奖励变体：

- **R_ans（值包含）**：最终答案里包含规范化的金标准返回值的比例；只奖励把工具产出的值报告出来，不比对参考答案。
- **R_tool / RF1_tool（工具集合）**：工具名的 recall 或其 F1 版本；F1 惩罚多余调用。
- **R_call / RF1_call（工具+参数）**：只有当参数也匹配时该调用才算命中；RF1 版本把调用当列表而非集合处理，从而惩罚重复调用和“灌水”。论文最终选用的即为 RF1_call。
- **R_hyb / RF1_hyb（混合）**：0.5(R_tool) + 0.5(R_ans)，同时控制调用与答案价值。

**（4）强化学习算法：GRPO（§4.4）**
- 对每个 prompt 采 n=5 条 rollout，组内对奖励做标准化得到 advantage，使用裁剪的策略梯度步更新。
- 学习率 1e−6。训练基于 slime post-training 框架，由 Megatron-LM 更新策略，SGLang server 生成多轮 rollout。两个起点（RL-only 与 SFT→RL）使用完全相同的优化器设置。

### 2.3 与旧方案的结构性对比

| 维度 | CheMatAgent（HE-MCTS） | 本文方案 |
|---|---|---|
| 模型数量 | 4 个（策略、执行、PRM、ORM） | 1 个 |
| 每问题调用次数 | 随搜索树增长 | 1 次 |
| 所用的评论信号 | 学习型 PRM + ORM（GPT-4o 回归混合） | 程序化可验证奖励 |

## 6. 论文的主要结论与发现

1. **单一策略足以超越复杂的 HE-MCTS 流水线**。在 Qwen-2.5-7B 上 Tool F1 达到 95.76%（对比 M3 的 90.80%），Return F1 达到 88.89%（对比 81.10%）；在 Llama-3.1-8B 上 Tool F1 95.93%（对比最强 M3 的 92.47%）、Return F1 89.70%（对比 M2 的 86.36%）。相应改进为 Tool F1 +5.5%/+3.7%，Return F1 +9.6%/+3.9%。在工具选择和返回值预测方面全部取得全面领先，且推理成本远低于搜索方案。

2. **Pass Rate 的结果与骨干有关**：Qwen-2.5-7B 上以 68.50% 微弱领先最强的搜索配置 67.32%；Llama-3.1-8B 上为 64.00%，落后 M2 的 72.30%。但两个单策略模型都优于所有 CoT/SFT 基线（GPT-4o-mini 58.00、Claude-3.5-Sonnet 57.00、ChemLLM 53.00、Llama-I∗ 55.00）。

3. **参数精度是仅存的短板**：HE-MCTS 在参数 precision 上仍领先（Qwen 骨干：89.32 vs 88.35；Llama 骨干：95.12 vs 89.50）。但这以四模型和每次提问的树搜索为代价。与报告全三项参数的 Llama-I∗（SFT）相比，本文模型在全部参数列上均领先。

4. **SFT 比 RL 贡献更大**：在三个骨干上，SFT-only 在几乎所有 F1 列和 Pass Rate 上超过 RL-only。原因在于 SFT 逐 token 接触金标准轨迹，RL 只能看到一个标量奖励；且 SFT 训练了如何组织最终答案而奖励函数不检查答案。

5. **RL 的作用主要是提高工具 precision**：RL-only 唯一全面占优的是 precision 类指标，这与下一结论相印证。

6. **F1/列表型奖励语义是防止奖励黑客的关键**：去除精度惩罚后（R_call），策略通过疯狂调用工具（每问平均 18.33 次、49.6% 重复率、97% 耗尽调用预算）压榨 recall；一旦引入 F1 惩罚，所有训练行为回归正常（每问约 3.1 次调用、几乎无重复、全部正常终止）。仅这一项修正让 Tool F1 从 32.82 跃升到 95.38——足以说明该设计的重要性。

7. **把答案值纳入奖励不但无益反而有害**：RF1_hyb 要求金标准返回值逐字出现，但很多数值工具结果在细节上有合理漂移（92% 的值在 1% 误差内与 57% 精确一致），这个含噪信号会导致训练不稳定。因此不直接检查答案反而更好。

8. **出现了一种监督无法提供的自修复能力**：模型在读到执行错误（如参数名错误）后能自行纠正并重发调用（图 3 案例）。由于金标准链只包含成功调用，这种从执行反馈中自我修复的行为不可能是从监督中学到的，只可能是 RL 奖励信号在线索下涌现的。

## 7. 优点

- **简洁优雅的方法论**：将整个工具使用流程压缩为单个模型、单次前向生成，不需要训练多个模型、不用搜索、不依赖 LLM 裁判，工程复杂度大幅降低。论文以受控对比证明前 SOTA 的几乎所有收益都能用简单训练方案获得。
- **高水平的对比公平性**：复用对方的 benchmark、工具池、评分方式、骨干网络与评卷 prompt，使结果能干净地归因于训练方案本身而非数据或评估差异。报告了每个骨干在相同 rollout 协议下的未训练基线，以区分训练效果与评估框架效果。
- **程序化奖励设计精细且系统化**：把奖励拆成答案、工具集合、调用（工具+参数）和混合层次，逐一分析其对训练行为的诱导，系统梳理了各组合的权衡和失败模式，深入剖析了奖励黑客问题。
- **奖励设计的部分归因分析做得好**：如表 3（训练阶段贡献）与表 4（奖励消融）的设计都能清晰分离某一因素对结果的影响。
- **真实执行反馈**：训练和评估中均真实运行工具，mask 掉服务器生成的 token，使模型学到真正的因果依赖和参数传递能力。这是许多模拟式工具训练框架未能做到的。
- **自我修复现象的发现与呈现**：通过完整的训练中途示例展示模型如何从执行错误中恢复，是一种可复现的、超出监督信号范围的涌现行为，值得进一步挖掘。
- **恰当地报告了不对称的比较劣势**：如实指出其奖励不针对最终答案做优化而 CheMatAgent 的 ORM 专门做了这一点，在 Pass Rate 可比性上坦诚承认部分劣势源自目标偏差而不只是能力问题。

## 8. 不足与局限

- **实验范围局限**：仅在一个 benchmark 的单个子集（ChemToolBench 多工具综合化学，200 条测试）上测试；没有在材料 split、单工具场景或其他科学领域做验证，结论的泛化

性不足；训练集仅 1566 条，规模较小，未检验数据规模变化对方法的敏感性。

- **Pass Rate 的不一致**：在 Llama 骨干上明显落后于最强搜索基线（64.00 vs 72.30），论文将其归因于最终答案未被奖励函数优化，但这同时也暴露了该方法在满足外部评卷标准上的短板——需要更多证据说明这一差距是可修复的而非系统性的。

- **奖励信号的噪声与局限**：RF1_call 要求参数与金标准逐值匹配，但工具返回值的数值漂移（92% 在 1% 误差内、57% 精确一致）说明金标准本身存在时效性与精度噪声；论文剔除了 57 条因实时服务导致返回值过期的数据，说明数据管线依赖实时工具服务，这会给复现带来不确定性。

- **未披露关键训练资源细节**：未给出 GPU 型号、数量、总训练时长，也没有报告 rollout 的实际耗时与工具调用成功率；在强调"每次提问仅需一次模型调用"的低推理成本优势时，缺少端到端延迟与 token 开销的量化对比数据支撑。

- **缺乏鲁棒性与方差检验**：评估全为贪心解码下单次生成，未报告多次采样下的方差或 pass@k；也未测试工具暂时不可用、超时、返回格式变化等真实环境扰动下的表现。

- **骨干规模覆盖有限**：仅在 4B/7B/8B 规模上验证，未尝试更大模型，无法判断该方法在更大规模下是否依然优于搜索方法，或是否会出现新的奖励黑客模式。

## 9. 对未来工作的启发与改进方向

- **更精细的奖励层次设计**：可将程序化奖励与轻量级验证器结合，例如对数值答案按相对误差容差打分而非逐字匹配，在保留可验证性的同时缓解金标准噪声；或对最终答案引入基于规则的关键要素检查，以弥补 Pass Rate 方面的短板。

- **跨领域拓展验证**：将"单策略 + RLVR"配方推广到其他工具密集的科学领域（如生物信息学、量子化学、材料设计），以检验其通用性——这是该结论能否从化学走向通用 agent 训练的关键一步。

- **规模化与替代关系研究**：在更大的骨干模型上检验单策略方法是否依然保持对搜索方法的优势，并系统研究"搜索树扩展"与"模型规模/训练量"之间的替代关系，为资源分配提供更普适的指导。

- **鲁棒性训练**：在训练中引入工具失败、超时、返回异常等噪声，使模型学会更通用的错误恢复策略，而非仅在单一成功路径上泛化。

- **更细粒度的 RL 归因分析**：对 RL 阶段的每个 rollout 做逐轮 advantage 分析，揭示哪些工具调用模式被强化、哪些被抑制，为奖励设计提供更系统的实证依据。

## 10. 综合评价

这篇论文以"化繁为简"为叙事主线，通过严谨的受控实验证明了一个重要观点：在化学工具学习任务上，此前 SOTA 所依赖的多模型、分层搜索架构并非必要——一个经过 SFT 预热与可验证奖励 RL 训练的单策略模型，在单次前向生成中即可达到乃至超越搜索方法的工具选择与返回值性能。其方法设计干净、奖励消融深入、公平性控制到位；自我修复这一超出监督信号范围的涌现现象的发现，也为理解 RL 训练中 emergent behavior 提供了有价值的案例。同时，其实验范围偏窄、Pass Rate 短板未完全解决、训练细节披露不足等局限，决定了其结论需在更广泛的基准与模型规模上进一步验证。总体而言，这是一项方法简洁、证据扎实、对工具学习与 RLVR 社区具有明确参考价值的工作，其"更少即更多"的核心信息具有较强的说服力与启发性。
