## 摘要
分子嵌入模型可作为计算化学和药物发现的基础设施，其中可复用的向量表示支持性质预测、虚拟筛选和检索。大多数分子编码器是围绕单一分子视图构建的专门模型，产生无条件的向量，且没有语言接口来改变表示。我们探究多模态大语言模型（MLLMs）——天然处理图像、文本和符号输入——是否能够作为通用分子嵌入模型，根据分子特征和自然语言语义上下文生成条件嵌入。我们引入了MolEmb，一种轻量级框架，通过双向对比目标将分子特征与文本描述在共享嵌入空间中对齐，从而适配MLLMs。由此产生的嵌入模型在分子性质预测上具有竞争力，并支持同一空间内的跨模态分子-文本检索。我们进一步引入了MolCAR，一个用于上下文感知检索的诊断基准，并发现上下文感知分子嵌入主要是一种监督的数据属性。这些结果表明，MLLMs不仅是化学助手或生成器，而且是通往通用分子嵌入模型的可行且可扩展的路径。

## Abstract
Molecular embedding models can serve as foundational infrastructure for computational chemistry and drug discovery, where reusable vector representations support property prediction, virtual screening, and retrieval. Most molecular encoders are specialist models built around a single molecular view, producing unconditional vectors with no language interface for varying the representation. We ask whether multimodal large language models (MLLMs), which natively process images, text, and symbolic inputs, can instead serve as \emph{general molecular embedding models} that produce embeddings conditioned on both a molecular profile and a natural-language semantic context. We introduce \textbf{MolEmb}, a lightweight framework that adapts MLLMs by aligning molecular profiles with textual descriptions in a shared embedding space using a bidirectional contrastive objective. The resulting embedding model is competitive on molecular property prediction and supports cross-modal molecule--text retrieval in the same space. We further introduce \textbf{MolCAR}, a diagnostic benchmark for context-aware retrieval, and find that context-aware molecular embedding is primarily a data property of the supervision. These results suggest that MLLMs are not merely chemistry assistants or generators, but a viable and extensible route to general molecular embedding models.

## 2. 方法论：核心思想、关键技术与算法流程

### 2.1 形式化定义

- 论文用定义方式明确区分三个通常纠缠的角色：
  - **分子身份 `m`**：底层分子；
  - **分子视图档案 `P(m)`**：该分子当前可获得的观测，如 2D 图像、SMILES、构象等；
  - **语义上下文 `c`**：决定嵌入“按照什么任务或语义视角”生成。
- 定义**通用分子嵌入模型**：
  \[
  E_\theta: \mathcal{V} \times \mathcal{C} \rightarrow \mathbb{R}^d,
  \quad
  z_c(m) = E_\theta(P(m), c)
  \]
  其中 \(\mathcal{V}\) 是多视图产品的笛卡尔积空间，\(\mathcal{C}\) 是自然语言指令集合。
- 该设定带来“上下文感知嵌入族”：
  \[
  Z(m)=\{z_c(m): c\in \mathcal{C}\},
  \]
  强调同一分子可根据任务不同被移动到共享空间的不同区域。

### 2.2 用 MLLM 实现该定义

- 输入序列由格式化函数构造：
  \[
  x(m,c)=\phi(P(m), c)
  \]
- 用 MLLM 的隐藏状态序列 \(H_\theta(x)\)，经池化函数 \(\rho\)（取 **EOS 位置隐藏状态**）得到定长向量：
  \[
  E_\theta(P(m), c) = \rho\big(H_\theta(x(m,c))\big)
  \]

### 2.3 MolEmb 对齐训练流程

- 保持预训练 MLLM 骨干冻结，只加入 **LoRA 适配器**（同时作用于语言和视觉模块）。
- 对于每个“分子-描述”对 \((m_i, t_i)\)：
  - 分子嵌入：固定编码指令 \(c_{\text{enc}}\)，用同一骨干编码多视图分子档案；
  - 文本嵌入：将描述文本送入同一骨干；
- 优化**双向对比学习（InfoNCE）**损失：
  \[
  \mathcal{L} = \frac12 \left[\mathcal{L}_{\text{NCE}}(z^{\text{mol}},z^{\text{desc}})
  + \mathcal{L}_{\text{NCE}}(z^{\text{desc}},z^{\text{mol}})\right]
  \]
  其中相似度为余弦相似度，训练时温度 \(\tau=0.07\)。
- 由此得到的模型兼具三个功能：
  - **性质预测**：加轻量 MLP 头；
  - **跨模态检索**：分子和文本共处一个 \(R^d\) 空间；
  - **上下文感知嵌入**：通过改变指令 \(c\) 将同一分子导向不同区域。

## 3. 实验设计：数据集、基准与对比方法

### 3.1 分子性质预测

- **下游任务数据**：8 个标准分子性质基准，使用 MoleculeNet/OGB scaffold split。
  - 回归：ESOL、Lipophilicity（lipophilicity）、FreeSolv，RMSE；
  - 分类：BACE、BBBP、ClinTox、Tox21、SIDER，ROC-AUC。
- **对比方法**：
  - 有监督 GNN：S-GIN、R-GIN；
  - 分子预训练方法：InfoGraph、GraphCL、MVGRL、AD-GCL、JOAO、GCL-SPAN、Mole-BERT、MolTextNet。
- **MolEmb 变体**：在三种 MLLM 骨干（Intern-S1-mini 8B、Qwen3-VL-8B、Qwen3.5-0.8B）上测试三种训练模式：
  - **Direct**：无分子-文本对齐，直接在目标任务上训练；
  - **MolTextNet**：先经过 MolTextNet 对齐，再下游微调；
  - **Mixed**：在 MolTextNet + KnowMol-100k + ChEBI-20-MM 混合语料对齐，再微调。
- 所有结果（含 MolEmb）用 3 颗随机种子均值±方差报告。

### 3.2 跨模态分子-文本检索

- 在 MolTextNet 的测试集上进行检索，候选池含 2,970 对（随机 R@1 ≈ 0.034%）。
- 指标：分子→文本（m2t）与文本→分子（t2m）的 R@1、R@5、R@10。
- 对比对象：通用多模态嵌入模型 **Qwen3-VL-Embedding-8B**（未针对分子对齐），以及经过 MolEmb 对齐的三个骨干。

### 3.3 上下文感知检索基准 MolCAR

- 论文新提出 **MolCAR**（Molecular Context-Aware Retrieval），用来测试任务指令能否使同一分子在不同任务文档之间正确“路由”。
- 构造方式：
  - 8 个任务族：BACE-1、BBBP、ESOL、FreeSolv、Lipophilicity、Tox21、ClinTox、SIDER；
  - 每个分子同时挂多个“任务上下文”文档，从而保持分子身份不变、只改变任务视角；
  - 评价分数：
    - Mol. R@1：正确分子是否在首位；
    - Doc. R@1/R@5、Doc. MRR：检索到“正确分子+正确任务”文档；
    - **Context R@1**：在同一分子内部，正确任务上下文是否排名第一（排除分子识别难度）。
  - 随机 Context R@1 基线约 40.4%（因为不同分子任务数不同）。
- 语料变体：
  - **MolCAR-Structured**：确定性模板生成的卡片；
  - **MolCAR-Natural**：由 Intern-S1(235B) 生成、结果锚定回真实观测值；
  - **MolCAR-Train**：由下游任务训练集构造，用于“继续对齐”。
- 训练设置：在 Mixed 对齐模型基础上继续对齐 MolCAR-Train，与无指令（NoInst）对比，检验指令是否提供增益。

### 3.4 额外实验

- **多视图消融**：多模态输入（2D 图 + SMILES）与 SMILES-only 对比；
- **检索保持检验**：检查 MolCAR 继续对齐后是否损害原来 MolTextNet 的检索性能；
- **t-SNE 可视化**：检验不同任务指令是否在嵌入空间形成分离结构。

## 6. 主要结论与发现

- **MLLM 可作为“基础良好”的分子嵌入起点**：即使没有分子-文本对齐（Direct），MLLM 隐藏状态已经能达到很多图预训练方法的水平，尤其回归任务更明显。
- **分子-文本对齐是跨模态检索的前提**：通用的多模态嵌入模型 Qwen3-VL-Embedding-8B 在分子检索上的 R@1 只有约 3%，而经 MolEmb 对齐后 R@1 可以超过 83%（Intern-S1-mini 最好，最差 Qwen3-VL-8B 也超过 73%）。
- **上下文感知嵌入主要由“监督数据属性”决定**：
  - 仅用通用分子-描述语料对齐时，任务指令对 Context R@1 的提升只有 3–4 个百分点，接近随机基线（40.4%），说明嵌入族收敛到“近似坍缩

状态’，即不同指令嵌入几乎坍缩到同一区域；而经过 MolCAR 目标语料继续对齐后，Context R@1 显著提升，说明“按需路由”的能力需要与目标分布相匹配的监督信号来激活，无法凭空涌现。

- **继续对齐 MolCAR 不会显著损害原有检索能力**：在 MolTextNet 测试集上，MolCAR 继续对齐后的 R@1 与仅 Mixed 对齐时基本持平或仅有小幅波动（仍在同一量级内），说明上下文感知对齐与通用分子-文本对齐之间不存在剧烈冲突，具备增量式扩展的可行性。
- **多视图输入带来实际增益但幅度有限**：2D 图 + SMILES 的双视图输入在多数任务上优于 SMILES-only，直观上合理——2D 结构图与线性序列提供了互补的归纳偏置。但这一增益并非在所有骨干上都稳定显著，说明 MLLM 视觉编码器对化学结构的感知仍存在结构偏差。
- **任务指令在嵌入空间中形成语义分化**：t-SNE 可视化显示，经过 MolCAR 对齐后，同一分子在不同任务指令下产生的嵌入会按任务类别形成若干分离簇，而未经指令对齐的模型则几乎无法区分这些上下文。这与 Context R@1 的量化结果相互印证。

## 7. 局限性与开放问题

- **概念验证性质**：论文虽证明了“MLLM 作为通用分子嵌入器”的可行性，但并未宣称已达到生产级能力；其下游评测仅限性质预测与检索，距离“通用”仍有相当距离。
- **上下文多样性不足**：本文的“语义上下文”局限于性质预测任务的简单指令（如“预测水溶性”），没有涵盖更复杂的查询式上下文、推理链上下文、多轮对话上下文等。真实科研场景中，用户往往用一段描述而非单句指令来表达需求。
- **多视图范围有限**：虽然论文强调“多视图”，实际使用的视图仅限于 2D 图和 SMILES；3D 构象、分子指纹、IUPAC 名、光谱等信息虽在定义上被纳入，却未进入实验。这与题目中的“多视图”存在一定落差。
- **嵌入空间的解释性不足**：MLLM 获得的分子嵌入是 3000+ 维的高维连续向量，没有像图神经网络那样天然保留原子/键级局部信息；用户难以知道嵌入中哪些维度编码了哪些化学语义。
- **评估基准的领域覆盖面窄**：MolCAR 和下游任务覆盖的均为药物小分子的物理化学性质与生物活性；对于材料分子、聚合物、无机晶体、反应产物等“分子嵌入”常见应用场景并未验证。
- **对 MLLM 骨干的依赖没有被充分解耦**：三个骨干在视觉塔、语言塔和融合机制上都不同，论文没有对骨干本身进行消融实验，无法确定哪些架构特质（如视觉 tokenizer 的分辨率、Qwen3 的混合注意力）对最终结果贡献更大。
- **算力成本与可复现性**：论文没有公布精确的 GPU 小时数，也未给出代码或模型权重链接（以本文现有信息看），这削弱了其他实验室独立验证该结论的可能性。
