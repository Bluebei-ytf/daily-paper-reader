## 摘要
系统化的国际纯粹与应用化学联合会（IUPAC）名称是化学文献、专利和数据库中传达分子结构的标准。我们介绍了NISPO，一个基于RDKit的开源Python包，用于生成IUPAC名称。NISPO是通过使用OpenAI的Codex和GPT-5.5模型的代理式自我改进循环开发的。如果开源OPSIN工具能将生成的名称解析回输入结构，则该名称被视为正确。在此目标的指导下，代理针对SureChEMBL中的268万个分子实施并改进了NISPO，使该工具在包含1.03亿个PubChem分子的保留集上实现了98.1%的往返准确率。NISPO可在https://github.com/oxpig/nispo免费获取。

## Abstract
Systematic International Union of Pure and Applied Chemistry (IUPAC) names are standard for communicating molecular structures in chemical literature, patents, and databases. We introduce NISPO, an open-source RDKit-based Python package for IUPAC name generation. NISPO was developed by an agentic self-improvement loop using OpenAI's Codex with the GPT-5.5 model. A generated name was considered correct if the open-source OPSIN tool parsed it back to the input structure. Guided by this objective, the agent implemented and refined NISPO against 2.68 million molecules from SureChEMBL, resulting in the tool achieving 98.1% round-trip accuracy on a held-out set of 103 million PubChem molecules. NISPO is freely available at https://github.com/oxpig/nispo.

## 6. 主要结论与发现

- **准确率**：NISPO 在 SureChEMBL 开发集上达到 **98.7%** 往返准确率，在 PubChem 1.03 亿分子测试集上达到 **98.1%**，接近商业工具 Lexichem 的 99.0%。
- **命名能力分阶段涌现（Emergence in phases）**：
  - 结构简单的分子（无环分子）在约 5 小时内就达到 97% 准确率；
  - 三环分子、稠环和螺环分子的命名能力需要超过 16 小时的迭代才成熟；
  - 初始版本仅基于 9,143 个分子、不到 20 小时开发，即在 PubChem 测试集上达到 70.6% 准确率，说明代理实现了通用命名规则而非死记硬背。
- **多目标优化的挑战**：代理难以并行优化多个目标，往往会因任何指标回退而立即回滚更改；采用“边界约束 + 单目标优化”策略后效果显著改善。
- **命名质量**：NISPO 生成的名称**有效但非首选**（valid but non-preferred）。例如：
  - 使用“boc”、“triflyloxy”等 OPSIN 支持但非 IUPAC 标准的缩写；
  - 父结构选择与 IUPAC 建议不同（如用“tryptamine”而非“indole-3-acetamide”）；
  - 仍可能产生冗长输出（如在可简写为“butane-1,4-diyl”处使用嵌套的“1-(1-(1-(1-...methyl)methyl)methyl)methyl)”）；部分分子使用完整的 von Baeyer 命名而非保留名（如 quinoxaline、phenoxathiine）。
- **代码质量**：NISPO 代码不符合传统人工代码质量标准（单个脚本含 22,203 行），但论文明确指出这并非当前用例的必需属性。
- **方法学贡献**：证明了**代理式自我改进循环**可以在有可验证目标函数的条件下自主开发科学软件。

## 8. 不足与局限

- **命名合规性不足**：NISPO 生成的名称虽能被 OPSIN 解析，但**不符合 IUPAC 蓝皮书的首选命名规范**（例如使用非标准缩写、截断、父结构选择不直观等），因此不适合需要严格 IUPAC 命名合规场景的应用。
- **单一评估标准**：以 OPSIN 往返成功率为唯一客观指标，**过度依赖 OPSIN 的解析特性**（如对“alpha-oxotryptamin”截断形式的容忍），可能导致 NISPO 的命名规则偏向 OPSIN 的“口味”而非真正的化学命名规范。
- **代码可维护性差**：单个脚本 22,203 行，代码结构不符合工程最佳实践，**不利于社区维护和二次开发**。
- **开发成本极高**：200 亿 token 的消耗意味着开发成本非常昂贵（虽然是一次性成本），其可复制性存疑。
- **缺少与同期工具的对比**：未与同期发布的 OpenClatura 进行实验对比，降低了横向可评估性。
- **评估集有重叠**：约 2.27% 的 PubChem 测试集分子来自开发集 SureChEMBL，尽管占比很小，但严格意义上并非完全独立的“held-out”评估。
- **测试筛选条件限制**：评估仅限于特定元素集合、单片段、≤50 重原子的有机分子，**未覆盖**有机金属化合物、同位素标记物、多片段盐类等更广泛的化学空间。
- **无消融实验**：未系统量化各设计决策（如课程策略、防作弊约束、目标边界设定）对最终性能的具体贡献。
