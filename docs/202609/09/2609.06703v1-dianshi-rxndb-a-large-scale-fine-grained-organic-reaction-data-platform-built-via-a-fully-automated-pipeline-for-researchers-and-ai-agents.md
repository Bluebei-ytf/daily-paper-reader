## 摘要
高质量的结构化有机反应数据对于发展化学人工智能（AI4Chem）至关重要，然而这些知识中的大部分仍分散在专利文本、图像和反应流程图中。我们提出了DianShi-RxnDB，一个大规模、细粒度的有机反应数据平台，通过集成了专利文本、图像和反应流程图的完全自动化提取与标准化流程构建而成。其语料库涵盖1976年至2025年间美国专利商标局（USPTO）和欧洲专利局（EPO）发布的有机合成专利，产生了约2400万个反应实例，其中约1480万个（61.7%）通过了自动资格检查。每个实例代表一个特定的单步实验，记录了参与者、作用、数量、温度、反应时间、产率、实验步骤以及与来源专利的溯源链接。在对1300个抽样合格实例进行的人工评估中，微观平均字段级准确率为92.95%。与Pistachio的匹配比较进一步显示其在去重记录数量、表示粒度和字段级精确匹配方面的优势。该平台提供了一个网络研究工作台，用于记录的搜索、筛选、比较和来源验证，并提供了一项模型上下文协议（MCP）服务，为AI智能体提供可组合的结构化检索工具。DianShi-RxnDB可在https://dianshi.opendatalab.org.cn/访问。

## Abstract
High-quality structured organic reaction data are essential for developing artificial intelligence for chemistry (AI4Chem), yet much of this knowledge remains dispersed across patent text, images, and reaction schemes. We present DianShi-RxnDB, a large-scale, fine-grained organic reaction data platform built via a fully automated extraction and normalization pipeline integrating patent text, images, and reaction schemes. Its corpus covers organic synthesis patents from the USPTO and EPO published between 1976 and 2025, yielding approximately 24 million reaction instances, of which approximately 14.8 million (61.7%) pass automated qualification checks. Each instance represents a specific single-step experiment recording participants, roles, quantities, temperatures, reaction times, yields, experimental procedures, and provenance links to source patents. In a manual evaluation of 1,300 sampled qualified instances, the micro-averaged field-level accuracy was 92.95%. A matched comparison with Pistachio further indicated advantages in deduplicated record counts, representation granularity, and field-level exact agreement. The platform provides a Web research workbench for searching, filtering, comparing, and source-verifying records, and a Model Context Protocol (MCP) service offering AI agents composable structured retrieval tools. DianShi-RxnDB is available at https://dianshi.opendatalab.org.cn/ .

- **总体目标**：构建一个同时满足“大规模 + 细粒度 + 实例级实验细节 + 来源可定位 + 对研究人员和AI智能体双接口可用”的开源有机反应数据平台，从而解决现有资源在数据完整性、可访问性和结构化一致性方面的核心痛点。

## 二、方法论：核心思想、关键技术细节与流程

### 2.1 核心思想

- 通过**全自动的信息抽取与标准化流水线**，将专利文献中分散在文本、图片和反应式中的有机合成实验知识，转化为结构化、细粒度、带来源溯源的 **Reaction Instance（单步反应实例）** 记录。
- 数据组织围绕 **Substance – Reaction Instance – Reaction Group – Reference** 四类核心对象及 Reaction Template 建立结构化关系，支持从特定反应记录到来源专利的逐级溯源与验证。

### 2.2 数据构建流程（关键阶段）

论文以 `表 2` 完整展示了从源专利到抽取语料的处理流水线：

1. **源专利收集**：汇集 USPTO 和 EPO 共计 20,256,438 条专利记录（USPTO 12,377,492 条 + EPO 7,878,946 条）。
2. **IPC 有机化学相关性过滤**：保留 2,512,925 条。
3. **源内合并与去重**（合并同一来源的重复申请与不同公开版本）：保留 1,968,230 条。
4. **USPTO 与 EPO 跨源去重**：保留 1,757,755 条。
5. **去除无可用全文的记录**：最终 **1,580,939 篇专利文献**进入反应抽取流水线。

### 2.3 自动抽取与标准化流水线

- **多模态覆盖**：流水线自动解析专利文本、可解析图片与反应式。其中 DeepSeek-V3-0324 主要负责处理专利实验文本；MinerU.Chem 负责图片和反应式中的化学信息解析。
- **结构化字段抽取**：对每个单步反应记录 Reaction Instance，抽取并组织以下信息类别：
  - 反应表示（反应物-产物结构、Reaction SMILES）
  - 参与物及角色（Reactant / Product / Reagent / Catalyst / Solvent）
  - 实例级用量（数量、当量、产物量）
  - 反应条件（温度、时间、压力、气氛等）
  - 结果信息（产率等）
  - 实验过程（分步操作，定义了 38 种操作类型，如 Add、Stir、Filter、Concentrate、Purify、Quench 等，见附录表 B4）
  - 来源链接（来源专利、文内定位及来源内容）
- **化学结构归一化**：对具有可用结构信息的参与者，使用 canonical SMILES 表示分子结构。
- **自动质检机制**：使用 RXNMapper 生成原子映射，并检查原子守恒等规则；通过者标记为“合格实例（qualified）”，未通过者保留在数据库中但标记为“不合格”。数据库中两类记录均保留抽取信息与来源关系。

### 2.4 核心对象的关系模型

- **Reference**：来源专利文档对象，链接多个 Reaction Instance。
- **Substance**：化学物质量记录，包含名称、分子式、分子量、canonical SMILES、InChI 等。
- **Reaction Participant**：连接 Substance 与 Reaction Instance 的关系，记录参与角色。
- **Reaction Instance**：具体单步反应记录（数据库核心粒度）。
- **Reaction Group**：按归一化的反应物–产物相同组合聚合多个 Reaction Instance，**不合并**各实例的实验条件、产率、步骤和来源信息，以支持同反应条件下的多记录比较。
- **Reaction Template**：基于 SMARTS 的更抽象的反应变换表示，数据库使用 LocalRetro 和 RDChiral 分别生成独立模板集合。

1. **规模化数据构建可行**：通过完全自动化流水线，成功从约 158 万篇 USPTO/EPO 专利文档中构建出约 2,400 万个细粒度反应实例，其中约 1,480 万条（61.7%）通过自动化质量评估，证明无人工逐条整理的大规模反应数据构建路径可行。
2. **字段质量可靠**：在合格实例总体中，五个核心字段（Yield、Reactant、Reagent、Catalyst、Solvent）的微观平均准确率达到 92.95%，其中 Catalyst 最佳（97.31%），Reagent 最弱（84.62%）。
3. **相对商业基线有竞争力**：与 Pistachio 的匹配比较中，DianShi-RxnDB 在去重后记录数量（1.368 倍）、表示粒度（角色细分、stage 对象、workup 字段、验证诊断）及全部六个评估字段的来源锚定精确一致率方面均显示优势。
4. **双接口设计有效**：Web 研究工作台支持研究人员的交互检索、实例比较和来源核验；MCP 服务支持 AI 智能体进行结构化多步检索；两者在同一数据基础上互补工作，可通过共享的对象标识与来源信息互相衔接。

## 七、方法或实验设计亮点

- **全自动化流水线**：覆盖文本、图像和反应式多模态内容，实现端到端的大规模结构化反应数据生产，具备可扩展性。
- **细粒度实例级组织**：以具体单步实验（Reaction Instance）为最小数据单元，而非以文档级或反应级粗粒度记录，支持对实验条件同条件下的实例比较。
- **完善的来源溯源设计**：每条 Reaction Instance 均链接到来源专利和段级定位，Web 界面支持结构化记录与原文同屏对照核验，显著增强数据可信度。
- **双接口架构**：同一数据基础同时服务人类研究人员（Web 工作台）和 AI 智能体（MCP），并支持两者间通过数据库 ID 和化学表示进行衔接，且为非商业用户免费开放——在现有专业数据库中罕见。
- **丰富的过程结构化定义**：定义 38 种实验操作类型，将自由文本实验步骤映射为结构化操作序列。
- **不合格实例保留策略**：未通过自动质检的记录仍保留在数据库中，不丢弃潜在有效信息，同时明确区分合格/不合格状态以避免误用。

## 八、不足与局限

- **数据覆盖范围有限**：仅覆盖 USPTO/EPO 专利（1976–2025），不含期刊论文和未发表实验知识；Pistachio 的期刊数据及 Reaxys/CAS 的更长历史回溯范围不在其内。
- **内部质量评估的覆盖不足**：仅评估合格实例总体的 5 个字段，未覆盖不合格实例（约占 38%），也未评估记录整体正确性、数据库召回率等指标。
- **字段级准确率不等于整体可靠性**：Reagent 字段准确率最低（84.62%），试剂与后处理物质、角色边界的混淆仍是系统性弱点；多步骤实验合并、跨段落上下文解析不完整等问题可能导致部分记录结构不准确。
- **外部对比公平性受限**：Pistachio 对比使用版本（2025Q2）落后于论文写作时的最新版本（2026Q2）；比较仅基于百篇级匹配样本，不排除样本偏差；两组数据计数口径不同，资源级数量不可严格互比。
- **安全与合规风险**：结构化记录及 AI 智能体的整理结果可能存在遗漏或错误，涉及实验安全、临床/监管、专利评估、生产条件选择等高风险用途时，论文明确建议需由专业人员结合完整上下文审核，不能直接替代专业判断。
- **商业使用受限**：Web 与 MCP 访问仅对非商业用途免费，商业使用需额外授权。
- **技术细节待披露**：论文仅提供能力层面的流水线概述，抽取和标准化流程的具体技术细节留待后续技术报告，当前读者难以复现或完全评估其方法学。
